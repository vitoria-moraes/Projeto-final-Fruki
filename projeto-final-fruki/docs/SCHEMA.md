# Schema esperado (referência)

> **Não execute este DDL em produção sem revisar.** Ele documenta o que as entidades
> JPA esperam. O `application.yml` usa `ddl-auto: none`, então nada é criado
> automaticamente.

---

## 1. Tabelas transacionais (Supabase/PostgreSQL)

### `cliente` — mapeada por `ClienteEntity`

| Coluna | Tipo esperado | Regra |
|---|---|---|
| `cod_cliente` | bigint | PK (a entidade usa `Long`) |
| `nome_fantasia` | varchar | nome exibido |
| `cnpj` | varchar(14) | único (a API valida dígitos) |
| `cidade` | varchar | usada no perfil regional |
| `uf` | varchar(2) | RS/SC |
| `cod_hierarquia` | bigint | opcional |

### `tabela_preco` — mapeada por `TabelaPrecoEntity`

| Coluna | Tipo esperado | Regra |
|---|---|---|
| `id` | varchar | PK |
| `cod_produto` | varchar | código do item (com ou sem zeros) |
| `nome_produto` | varchar | usado para inferir a categoria |
| `preco_base` | numeric(12,2) | preço unitário |

### `fato_vendas` — mapeada por `PedidoEntity`

| Coluna | Tipo esperado | Regra |
|---|---|---|
| `id` | bigint identity | PK gerada |
| `cod_cliente` | bigint | FK lógica para `cliente.cod_cliente` |
| `data_venda` | date | data da venda |
| `valor_total` | numeric(12,2) | total calculado |

### DDL de referência

```sql
create table if not exists cliente (
    cod_cliente    bigint primary key,
    nome_fantasia  varchar(120),
    cnpj           varchar(14) unique,
    cidade         varchar(80),
    uf             varchar(2),
    cod_hierarquia bigint
);

create table if not exists tabela_preco (
    id           varchar(40) primary key,
    cod_produto  varchar(20),
    nome_produto varchar(160),
    preco_base   numeric(12,2)
);

create table if not exists fato_vendas (
    id           bigint generated by default as identity primary key,
    cod_cliente  bigint,
    data_venda   date,
    valor_total  numeric(12,2)
);
```

## 3. Como conferir o schema real

**Supabase (SQL Editor):**

```sql
select table_name, column_name, data_type
from information_schema.columns
where table_schema = 'public'
  and table_name in ('cliente', 'tabela_preco', 'fato_vendas')
order by table_name, ordinal_position;
```

**Databricks (SQL Editor):**

```sql
show columns in workspace.default.gold_recomendacao_b2b;
select count(*) from workspace.default.gold_recomendacao_b2b;
```

## 4. Pontos de atenção

1. `ClienteEntity.codCliente` e `PedidoEntity.codCliente` são `Long` (bigint), conforme o schema observado no Supabase.
2. O schema atual de `fato_vendas` não armazena status nem resumo dos itens; o histórico mostra valor e data.
3. `id_cliente` (Gold) e `cod_cliente` (Supabase) podem não ser o mesmo número. O
   enriquecimento com nome/cidade é best-effort.
4. `cod_item` pode estar com zeros à esquerda; o `CatalogoService` tenta `1`, `00001`
   e `0001`.
5. `tabela_preco` não tem coluna de categoria; a categoria é inferida pelo nome.
6. Não há migrations (Flyway/Liquibase). Este documento é a referência até que o
   schema real seja versionado.
